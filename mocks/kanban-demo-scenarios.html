Customer demo gaps

Identify and document open questions / functionality gaps for the 22 Sep session — sequencing or overlapping work, task shunting, work on hold, and Kanban→Gantt updates.

  • Current

    Task shunting when work is delayed

    Stramash today: only the booking on the card you move is relocated. Later same-phase bookings stay put — the held/deferred booking can jump over them (two cards for the same phase next week is possible). Same-phase “train” shunt is not built (intentionally undecided).

    Ask customers: Push following bookings when they collide, leave gaps / jump over, or leave later weeks for RM/EM? Also: preserve gaps between bookings?
  • Decided

    On Hold vs Defer

    Agreed distinction (validate with customers): On Hold = waiting on something external (client info, form, etc.). Defer = internal — practitioner won’t get to it this week, so chuck it to next week (+7). UI: defer is a drop zone under the On Hold column; card stays To Do / In Progress.

    Ask customers: Is that distinction clear? Does it match how they work? Would they misuse On Hold for “not this week”?
  • Open

    Sequencing & prep ↔ review overlap

    Gantt today has no hard restriction — you can place phases however you like. “Week overlap” on the Gantt often isn’t real calendar overlap (prep Mon / review Fri). Rules matter most for shunting / overtaking, not every Gantt drag. Setting level (template vs per-job override) still discovery. Hope: Kanban self-heals so RMs do less manual Gantt.

    Ask customers: How often do phases overlap in practice? When prep slips, should review move — A never · B only if prep would overtake review · C always cascade · D it depends on the job? How strict should we be on overtaking?
  • Open

    Blocking impact + next-worker signal

    Don’t move other people’s tasks with no warning. Prefer surface clashes (deadline / at-risk) and let humans/RM fix the hard cases (~80%). Not built: notifying the next-phase worker. On Hold impact modal needs a focused design pass (overlap-allowed vs non-overlap dates).

    Ask customers: Engagement deadline risk enough, or call out next-phase owners? Prefer warn-only vs hard-block when defer/hold puts review at risk?
  • Steve

    Kanban → Gantt parity / what’s live

    Every Kanban action must leave Gantt truthful. Source of truth for “what’s implemented” = Playwright / e2e tests in the repo (Steve to share link). Pre-demo work tracked under epic DEVO-30767.

    Steve: Send e2e / scenario test link; mark each demo scenario Built / Partial / Talk-track only.
  • Scope

    Who owns the schedule after hold/defer?

    Putting work on hold can throw later weeks out of whack (over-utilised, holidays). Ties to impact / next-worker signal. Assumption: practitioners schedule within Kanban guidelines; RM/EM for edge cases.

    Ask customers: After a hold, who fixes subsequent weeks — practitioner or RM/EM? Is there a common pattern across firms?
  • Open

    Done this week vs phase complete

    Unlike Jira “Done = finished forever,” dragging to Done often means done this week, then the product asks about future bookings. Easy to confuse in a demo — highlight explicitly.

    Ask customers: Which “done” do they mean most often at end of week?
  • Design

    At-risk / previous-phase signal on cards

    V1 preference: don’t hard-block defer/overtake — warn (“puts review at risk”) and/or signal the reviewer that prep is delayed/on hold. People talk in real life; we surface clashes.

    Design + Steve: Badge copy/treatment on review (and prep) cards for at-risk / previous phase on hold.

Prep ↔ Review overlap — effect on scenarios

Updated 14 Sep with Steve: no hard Gantt gates today; readiness should be visual signals not hard blocks; delay logic is same-phase first; cascading into review is a customer question (incl. “it depends”).

Working assumptions

  • Now: no restrictions on the Gantt — phases can overlap or even overtake.
  • Demo data: set jobs up with phases in a sensible order manually (“soft ordering” = we stage the example, not a product rule yet).
  • Week blocks ≠ calendar overlap: prep Mon + review Fri still look overlapped on a week Gantt.
  • Current move behaviour: only the card’s booking moves; it may jump over later same-phase bookings. Train shunt / preserve-gaps = not built.
  • V1 clash handling: warn / badge (at-risk, previous phase on hold) — don’t hard-block practitioners; they (or RM/EM) sort it in real life.
  • Sequencing + readiness signals are linked and desirable pre-demo if capacity allows.
Scenario Implication with overlap allowed
S01 Start Unchanged. Also show Kanban status on Gantt sidebar (To Do → In Progress) — ticket in DEVO-30767.
S05 Defer Only that prep booking +7. Review stays. Optional: at-risk signal on review if same week / overtake. Ask how strict to be.
S07 / S08 On Hold Not “review can’t start.” Highlight previous phase on hold / delayed. Reviewer card is not auto-frozen. Impact modal needs love (overlap vs non-overlap).
Shunting Today: move one booking only (can jump). Proposed ask: same-phase train ± preserve gaps. Cascading review = separate decision / “it depends.”

Kanban readiness flow

Sequencing and readiness are the same problem family. Prefer visual Ready signals, not hard gates. Revert/rework path is not in Stramash yet — demo Ready via workflow / third-party where possible, and separately discuss rework scheduling (ad hoc).

  • Talk-track

    B · Rework return (not built): reviewer reverts → preparer finishes returned work → reviewer sees Ready. May need ad hoc time (prep then review again).
