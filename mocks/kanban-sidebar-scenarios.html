4. Design decisions locked in this mock

  • Language: Sidebar (not drawer). Phase / Card / Milestone / Trait / Effort. Engagement not “Job” in practitioner UI.
  • High priority: solid danger Badge beside status, Figma chevrons-up Priority Indicator icon on the left — not a full-width magenta StatusCard banner; remove priority corner glyph from Sidebar header.
  • Overdue banner: Dayshape danger tokens (--surface-danger-subtle, --text-danger, --border-danger-subtle), same family as Overdue badge.
  • Overdue: banner above Booking Details (not on the Start/end row). Due Soon is out of scope until customer/work-type rules exist — do not ship a generic “soon” chip.
  • Readiness: visual Signal (Ready / Not Ready / awaiting client); warn StatusCard when previous phase incomplete — warn, don’t hard-block.
  • Effort in Details: show this week’s booking planned hours (not a separate estimate that disagrees with the booking).
  • Trait overflow: +N chip; black stacked tooltip listing overflow traits (board cards already use this pattern in the mock).
  • Milestone booking rows: Figma rail Status Done / InProgress / Current warn / Overdue / Upcoming; connectors solid or dotted. Week-of labels (This Week when current). Status label lives in a black tip on the left rail node (no status text/icon in the row end). Each row shows planned · spent hours (including bookings that aren’t yours — phase roll-up = sum of parts). Your In Progress: bold This Week. Someone else’s: quiet This Week, same blue rail. Avatar 24px + black name tip.
  • Phase headers: show aggregated planned effort for that phase next to the phase date. Phase badges use gantt aggregation colours (Prep blue / First Review green / Second Review purple) with tinted fill, matching outline, and a left colour swatch — same in Booking Details.
  • Engagement-only (no phases): no Milestones section — show a Bookings list (week rows) without phase grouping. Story JOB.
  • Key dates: Under Milestones — card rows (subtle surface + border): Client Delivery Deadline and Statutory Deadline (circle + flag each); title semibold left, date muted right; rail line between icons.
  • Status menu: Current row + transitions; single separator under Current (no double rule before Hold/Done).

5. Implementation checklist

Work top-down. Check Stories tab after each item. Keep Pinia as source of truth; Sidebar is presentation + transitions.

  • Header layout — traits row (overflow), engagement title/subtitle link, status control + High priority Badge, close. Match Stories PRI / TRAIT.
  • Status menu — open from Sidebar; transitions consistent with Board drop rules (incl. pooled To Do cannot go straight to Done — S04).
  • Status banners — keep Hold / Pending / Reverted / Done; add Overdue + readiness warn; tokens only; edit pens keep opening existing On Hold / Revert modals.
  • Booking Details — always titled Booking Details (card = booking); icon-only labels + tip; Phase (when phased), Start/end (editable pickers when the booking can be changed; read-only text when Done — story SCH-RO), Estimated Effort for this booking (pen → h/m with check to save / close to cancel; hours field focused on edit; no pen when Done), Signal, Assignee last. Stories RDY / NRDY / OVRD / EFF / SCH-RO.
  • Milestones — phase-level only; light collapsibles; phase effort totals; booking rows with planned/spent; key dates. Stories PH-* / S01b / S01c / S01d.
  • Bookings (engagement-only) — when there is no phase model, week list without phase groups. Story JOB.
  • Spacing — booking cell padding: name ~12px left, avatar ~12px right, vertical ~10px (see gallery CSS .Drawer-msCell*).
  • i18n — all new copy via t('kanban:sidebar…'); follow localisation howto.
  • Tests — update/add *.test.mjs for new visible behaviour (not DOM existence only). Follow taxapp-testing instructions.
  • A11y — tooltips keyboard-reachable; focus trap already in Sidebar — don’t break it. Status-menu keyboard (arrow keys / Escape) is future, not this release.

7. Out of scope for this handoff

  • Due Soon chip/rules — “soon” varies by customer and work type; keep exploratory rail labels in Stories if useful, but do not ship a Due Soon badge until rules are defined (SOON is reference only).
  • Status-menu full keyboard a11y for column moves without drag (future).
  • Board column drop zones / Gantt shunting (see kanban-demo-scenarios.html)
  • Creating new engagements from Sidebar
  • Changing Phase API contracts unless a Story cannot be met without data (prefer UI from existing fields first)
