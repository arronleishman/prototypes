Board model

A Card = one Booking (Task): one worker × hours × dates. Best practice is one Booking per Phase per week. The board is week-scoped.

Columns

To Do · In Progress · On Hold · Done

Status owner

Kanban Status lives on the Booking; Phase status is a roll-up.

Pooled vs scheduled

Pooled = unassigned, practitioner-led. Scheduled = pre-assigned worker.

Week lens

Navigate by week. Multi-week bookings share one status across weeks.

To Do
In Progress
On Hold
Done

Card lifecycle at a glance

New demand (S21)→ To Do→ Start (S01)→ In Progress→ Complete (S02/S03)→ Done

Side paths: To Do → Done without starting (S04, scheduled only) · To Do / In Progress → On Hold (S07/S08) · On Hold → resume (S10B) · Defer To Do (S05) · Reopen Done (S11/S20) · Put back to To Do (S19) · Return to Pool (S22).

Starting & completing work

Core drag lifecycle a practitioner uses every week.

S01

Start work

Practitioner Implemented
Action
Drag card To Do → In Progress.
Board
Card moves to In Progress. If a prior phase is still To Do, a warning toast may show (not a hard block).
Data / Gantt
Booking status → In Progress. Scheduled: no assignment change. Pooled: claim assigns the pool group; selected card starts, sibling pool bookings for that worker stay To Do; capacity updates.
Stramash
Try both scheduled and pooled cards on First Environment (Pinion).
S02

Complete work — no future bookings

Practitioner Implemented
Action
Drag In Progress → Done.
Board
Mark Complete modal captures effort. Card sits in Done for this week.
Data / Gantt
Status → Done; this week’s effort set to actual; capacity recalculates. No “future bookings” branch.
Stramash
Confirm effort modal and capacity change after complete.
S03

Complete work — future bookings exist

Practitioner Implemented
Action
Drag In Progress → Done when the booking has future weeks.
Board
Modal offers: Done this week (keep futures) or Phase complete (remove this worker’s future bookings) + effort.
Data / Gantt
Phase complete deletes this worker’s future bookings on the phase only; other workers untouched.
Stramash
Check next week for presence/absence of the card after each choice.
S04

Complete without starting

Practitioner Implemented
Action
Drag To Do → Done.
Board
Scheduled: Mark Complete modal, then Done. Pooled: drop blocked — must go via In Progress first.
Data / Gantt
Scheduled booking marked Done with effort captured.
Stramash
Verify pooled cards cannot skip straight to Done.
S11

Reopen completed work (as In Progress)

Practitioner Implemented
Action
Drag Done → In Progress (current week only).
Board
Status-only reopen; no modal; no new booking. Past-week Done is read-only.
Stramash
Confirm previous weeks cannot be reopened.
S19

Put work back to To Do

Practitioner Implemented
Action
Drag In Progress → To Do.
Board
Status-only; no modal or reason capture.
Stramash
Symmetric undo of S01.
S20

Reopen completed work as not started

Practitioner Implemented
Action
Drag Done → To Do (current week only).
Board
Status-only back to To Do; same week gate as S11.
Stramash
Pair with S11 when validating reopen rules.

Deferring work

“Not this week — later.” Different meaning from On Hold, but related mechanics.

S05

Defer unstarted scheduled work

Practitioner Implemented
Action
Drag scheduled To Do onto the On Hold column defer zone (not the hold zone).
Board
Card leaves this week and reappears as To Do next week. Deadline-breach modal can warn but still allow.
Data / Gantt
Booking dates shift +7 calendar days; stays To Do. Later weeks are not shunted in the current ship.
Stramash
Distinguish defer zone vs hold zone; check capacity on both weeks.
S06

Defer started work

Practitioner Out of MVP
Action (design)
Defer from In Progress with remaining-effort modal.
Today
Not a separate flow — use S08 On Hold when you cannot finish mid-progress.
Stramash
Do not expect a dedicated defer-from-In-Progress path.

Blocking & unblocking

Put work On Hold (reason + unblock date), then resume early manually.

S07

Block before starting

Practitioner Partial
Action
Drag To Do → On Hold (pooled work must be claimed / started first).
Board
On Hold modal: reason, unblock date, effort so far, remaining. Card stays visible in On Hold.
Data / Gantt
Selected booking can split (effort so far vs remaining hold booking). Full successor booking shunting is not implemented.
Stramash
Use scheduled To Do cards; confirm modal validation on efforts.
S08

Block mid progress

Practitioner Partial
Action
Drag In Progress → On Hold.
Board
Drop zones: On Hold (top) and optionally Revert to previous phase (bottom). On Hold / revert modals.
Data / Gantt
Booking split similar to S07. Spent effort can land in Done; On Hold portion does not count as capacity the same way.
Stramash
Exercise both drop zones where a previous phase name exists.
S10B

Unblock — resume now (manual)

Practitioner Agreed · verify on env
Action
Drag On Hold card back to To Do or In Progress before the unblock date.
Board
Target status applied; other held bookings for the group may return to To Do.
Data / Gantt
Prefers a current-week held booking; otherwise may move the earliest future hold into the current week. No reverse shunt of successors.
Stramash
This is the only way off On Hold today — automated S09/S10A are not built.

Review workflow

Reviewer ↔ preparer loop. Treat as incomplete on Stramash until persistence is solid.

S12

Review rejected (absorbs S14)

Practitioner (reviewer) Partial
Action
Reviewer rejects / reverts preparation work.
Board (target)
Reviewer card moves toward hold/pending; preparer gets a new To Do rework card. Modal can pick preparer (defaults to most preparation effort — former S14).
Today
UI / optimistic banners may exist; backend rework booking creation / persistence was still incomplete at last flow audit.
Stramash
Expect fragile behaviour; banners may vanish on reload.
S13

Rework completed

Practitioner (preparer) Depends on S12
Action (target)
Preparer completes rework; reviewer To Do becomes ready again.
Today
Blocked until S12 backend path is reliable.
Stramash
Look for readiness badge on the reviewer card once rework exists.
S14

Multi-preparer assignment

— Absorbed into S12
Note
No standalone scenario. S12 modal pre-selects the preparer with the most preparation effort; reviewer can change.

Creating & removing work

S21

Create demand / booking from the board

Practitioner In code & tests
Action
Create Booking from the board (engagement search, this / next / custom week).
Board
New card appears in the target week; toast if created outside the selected week.
Doc note
User-flow doc still marked pending as of an older audit; Critical Playwright Kanban.BookingCreation and UI modals are present on v4.
Stramash
Create against Pinion engagements on First Environment.
S22

Return to Pool

Practitioner (pool worker) Return shipped
Action
Drag eligible assigned To Do / In Progress onto the To Do column Return to Pool zone → confirm.
Board
Group bookings become pooled To Do; capacity drops. This is not delete.
Also
In Progress → Scheduled To Do can be status-only (keeps assignment). Pooled → Scheduled To Do claims without starting.
Stramash
Hard delete of work remains unresolved — use Return to Pool, not delete.

System automation (not practitioner-initiated)

These fire on dates or week open — mostly still design / partial.

S09

Automated unblock — not yet started

System Not built
Trigger
Unblock date reached for work that was never started.
Target
On Hold → To Do automatically.
Today
UnblockDate is stored but not consumed by a job. Only S10B leaves On Hold.
S10A

Automated unblock — resume

System Not built
Trigger
Unblock date reached for work that had been started.
Target
Same destination as S09 in current design (To Do). Kept as a separate ID for automation docs.
S15

Week rollover — In Progress, no futures

System + prompt Designed (POST V1)
Trigger
First board open in a new week with leftover In Progress.
Target
Modal: completed last week? Yes → Done previous week. Still going → split remaining into new To Do this week.
S16

Week rollover — In Progress, futures exist

System + prompt Designed (POST V1)
Trigger
Same as S15 when a future booking exists (not necessarily this week).
Target
Yes keeps futures; Still going can create a current-week booking. Contiguous booking already this week may auto-close old week without a modal.
S17

Week rollover — untouched To Do

System Partial
Today
Overdue indicator is built. Automatic booking roll into the new week is not.
Stramash
Expect overdue cues; do not expect auto-roll yet.
S18

Week rollover — was Done last week

System Agreed no-op
Behaviour
Card does not reappear; no new booking. Negative assert on Stramash.

Board UI practitioners also use (beyond Sxx)

Supporting interactions on the same Stramash Kanban surface. The public usability widget on Practitioner Kanban exercises these gap scenarios (S04, S06, shunting, S11/S20, S21, S22, S17) alongside the happy path — this map stays Stramash product truth; the widget is where we test the gaps.

Week navigation

Previous / next week via board controls; URL carries weekKey.

Capacity indicator

See weekly used capacity; updates on claim, complete, defer, return to pool.

Column filters

Filter cards within columns (phase / traits / search facets depending on build).

Engagement search

Find engagements when creating demand or navigating work.

Card sidebar

Open a card for engagement info, phases, milestones, booking dates, status banners.

Effort edit

Adjust effort from sidebar / effort controls (also prompted on complete / hold).

Phase readiness badges

Informational ready / not-ready cues from phase predecessors — not a hard start gate.

Due-date warnings

Defer and On Hold flows can warn when dates breach phase due / scheduled end.

Trait overflow & importance

Card shows traits (+N overflow) and importance cues.

Past-week Done lock

Historical Done cards are read-only with tooltip; reopen only in the current week.

Preceding-phase toast

Starting work while a prior phase is still To Do can show a warning toast.

Feature flag

Without Kanban access / flag, board routes can 404.

Practitioner vs system

Practitioner can

  • Start, complete, put back, reopen (S01–S04, S11, S19, S20)
  • Defer unstarted scheduled work (S05)
  • Hold from To Do / In Progress (S07, S08)
  • Manually resume from On Hold (S10B)
  • Create bookings (S21) and Return to Pool (S22)
  • Navigate weeks, filter, search, use sidebar, respond to readiness / due warnings
  • Claim pooled work by starting it

Not available / not MVP yet

  • Defer from In Progress (S06) — use On Hold
  • Full booking shunting on hold/defer
  • Automated unblock by date (S09 / S10A)
  • Reliable review rework loop (S12 / S13)
  • Delete work via unassign (Return to Pool ≠ delete)
  • Pooled To Do → Done shortcut
  • Week-rollover auto-roll (S17) and first-open modals (S15 / S16) as fully shipped automation
